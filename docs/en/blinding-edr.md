# 致盲与失能 - 瘫痪守卫者

本章节建议搭配芙蕾德莉卡的安全学习科普视频观看 [https://www.bilibili.com/video/BV1sQy3BpEQz](https://www.bilibili.com/video/BV1sQy3BpEQz)

在成功绕过静态查杀后，我们的 C2 载荷会面临 EDR 在内核层布下的回调、ETW 和 WFP 等严密监控。

要实现长久且隐蔽的控制，我们必须确保 EDR 对我们的关键行为**彻底失能**。我们将介绍两种针对动态监控的“致盲”战术。

---

## 1. 自带驱动攻击 (BYOVD) {#h-1-自带驱动攻击-byovd}

**BYOVD (Bring Your Own Vulnerable Driver)** 是红队针对内核监控的解决方案。其目标是利用系统信任获取 Ring 0 权限，从**系统最高维度**清除所有监控痕迹。

- **核心原理：** 攻击者自带一个**具有合法数字签名，但存在已知漏洞**的驱动程序。由于该驱动有签名，系统允许它加载到内核（Ring 0）。攻击者随后利用该驱动的漏洞，在内核中执行任意代码。

### 🚨 内核权限的终极用途：修改 `ntoskrnl` 结构 {#内核权限的终极用途修改-ntoskrnl-结构}

一旦获得了内核（Ring 0）权限，攻击者就可以执行“上帝”级别的，针对 EDR 监控的**外科手术**：

1. **定位核心结构：** EDR 注册的 **Ps、Ob、Cm** 等内核回调，其地址都存储在 **`ntoskrnl.exe`** 内部的特定或动态结构中。
2. **手术刀操作：** 攻击者可以编写代码，在内核中定位并遍历这些回调注册列表。
3. **清除回调：** 找到属于 EDR 驱动程序注册的函数指针，并将其从 `ntoskrnl` 维护的列表中**清空或替换**为无效值。

> **效果：** 这不仅仅是杀死 EDR 进程。这种操作是从**操作系统的心脏**中移除了 EDR 的监控“听筒”和“眼睛”。即使 EDR 守护进程重新启动，其核心监控功能（进程创建、句柄访问、注册表修改）也已经瘫痪，因为它的回调地址已被移除。

---

## 2. 用户态对抗：摘除守卫者的“眼睛”（WFP 操控） {#h-2-用户态对抗摘除守卫者的眼睛wfp-操控}

相比于 BYOVD 的复杂高危，利用 WFP (Windows Filtering Platform) 操控是一种**低成本、高效率**的局部致盲手段，旨在消除 C2 流量告警。

- **目标：** 瘫痪 EDR 通过在 WFP 中注册 Filter（过滤器）来实现的网络流量监控。

### A. 致盲原理：管理员权限的巧妙利用 {#a-致盲原理管理员权限的巧妙利用}

- **WFP 监控机制：** EDR 通过在 WFP 中部署 Filter 来检查 C2 流量（如检查可疑进程是否连接了外部 IP）。
- **关键突破口：** WFP 提供了用户模式 API（如 `FwpmFilterDeleteByKey0`）来管理其过滤器。经研究发现，Windows 对 WFP 的管理 API 在删除过滤器时，权限校验并不要求内核权限，**只需攻击者具有管理员权限（Administrator）即可**。

### B. 攻击过程与效果 {#b-攻击过程与效果}

1. **权限要求：** 攻击者需获取目标主机的管理员权限。
2. **定位与删除：** 调用 WFP API 遍历并识别出由 EDR (Provider) 创建的流量监控 Filter，并将其删除。
3. **最终效果：**
    - **流量隐身：** EDR 彻底失去对 C2 通信的监控能力，你的 Beacon 流量在 EDR 视角中**消失**，不会触发网络告警。
    - **隐蔽性高：** EDR Agent 进程本身**仍然在线**，其他监控模块未受影响。管理员在后台看到的 EDR 状态是“健康的”，不会触发守护进程拉起，但系统已处于“网络盲区”。

---

**总结：**

| 战术 | 攻击维度 | 目标 | 风险 | 效果 |
| --- | --- | --- | --- | --- |
| **BYOVD** | Ring 0 (内核) | Ps/Ob/Cm **回调结构** | 极高（可能 BSOD） | **永久性**清除内核监控功能。 |
| **WFP 操控** | Ring 3 (用户) | WFP **流量过滤器** | 低（仅需 Admin） | **重启前**清除网络监控功能。 |
