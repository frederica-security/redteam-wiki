# IM攻防：拓展攻击面与想象力

本章节中关于URL scheme，OAuth体系、浏览器漏洞的讨论，建议搭配芙蕾德莉卡的科普视频观看 [https://www.bilibili.com/video/BV1HhnHzPEcJ](https://www.bilibili.com/video/BV1HhnHzPEcJ)

## 为什么要把目光投向IM？ {#为什么要把目光投向im}

### 邮件：易于留样，难于挥发 {#邮件易于留样难于挥发}

咱们先聊聊邮件钓鱼面临的现实挑战。

邮件本身是**静态、持久化**的资产。一旦你的钓鱼邮件被安全网关捕获，样本就会被截留、沙箱分析，并迅速生成特征码，用于拦截后续的同源攻击。对于攻击者来说：

- **证据易留存：** 邮件内容、附件和链接 URL 都会被企业的邮件归档系统（Archive）永久保存。
- **防御集中化：** 企业在邮件网关上投入巨大，防御手段集中且成熟。

**IM 则拥有极佳的“挥发性”优势。**

IM 消息（尤其是像微信的“撤回”功能），可以在用户点击或被察觉后迅速清除痕迹。很多时候，攻击样本在被发现前就被删除，导致安全团队难以进行及时的恢复和取证。

### IM 的使用边界和信任优势 {#im-的使用边界和信任优势}

IM 的覆盖范围远超企业内部 IM 的“同事私聊”，它有独特且更宽泛的攻击价值：

- **更广的覆盖面：** 微信等应用深度覆盖了**朋友关系、外部合作方**，乃至许多**中小型企业**的核心办公场景，为攻击者提供了更丰富的社交工程入口。
- **信任感拉满：** 邮件是“陌生人的信件”，IM 则是“**朋友或熟人发的**”。这种天然的社交信任，是绕过人脑防御的第一道屏障。
- **防御薄弱：** 相较于邮件网关，企业在 IM 消息内容和客户端协议安全上的投入通常不足。

> **核心认知：** IM 攻击不再是简单的“发个钓鱼链接”，它利用的是现代办公流程中，信任的边界模糊和证据挥发性。

## 自动下载：最被低估的“无声渗透” {#自动下载最被低估的无声渗透}

### 发生了什么？你的电脑在偷偷“收垃圾” {#发生了什么你的电脑在偷偷收垃圾}

很多人可能没意识到，IM 客户端在接收文件时，经常会**自动地、静默地将文件缓存到你的本地电脑上**。你无需主动点击“另存为”。

> - **微信：** 文件自动下到本地缓存目录。
> - **钉钉/飞书：** 默认配置下，通常也会自动缓存到本地的 Download 或缓存目录。

### 这意味着什么？丝滑的攻击流程 {#这意味着什么丝滑的攻击流程}

传统钓鱼需要用户进行多次不自然的操作（下载 → 解压 → 双击）。

利用自动下载，攻击流程变得异常**丝滑**：

```text
攻击者：发送伪装的文件（如“年终奖表格.xlsx.lnk”）
系统：文件自动下载到本地（用户无感知）
用户：看到文件 → 双击
结果：直接中招，整个过程没有下载、解压等反常操作。
```

### 实战技巧：用 LNK 执行图片文件中的shellcode {#实战技巧用-lnk-执行图片文件中的shellcode}

**核心原理：**

1. 攻击者首先将恶意代码**隐藏**在一张正常的 **JPG 图片**文件的末尾。
2. 发送该 JPG 文件到聊天窗口（JPG 看起来无害，通常不会被拦截，且会自动下载）。
3. 发送一个 **LNK 快捷方式文件**，将其图标伪装成 Excel 或 Word 文档。
4. LNK 文件配置的执行命令是：**读取那张已下载到本地的 JPG 文件末尾的代码，并执行。**

**为什么有效？**

- 规避了对可执行文件和压缩包的拦截。
- 用户交互少，双击就上线
- 不用右键解压，避免一些完全不懂解压的非技术人员，直接在软件中双击lnk（实战中经常出现，让你血压上升）

## 外部群：免费的侦察入口 {#外部群免费的侦察入口}

### 场景：混入协作群 {#场景混入协作群}

现在很多企业用 IM 客户端与外部供应商或合作方沟通，通常会创建 **“外部协作群”**。

**问题来了：** 你作为外部人员混进群后，能看到什么？

| 信息类型 | 可见性 | 利用价值 |
| --- | --- | --- |
| 公司内部聊天记录 | ❌ 看不到 | - |
| **群成员列表** | ✅ 能看到 | 组织架构侦察 |
| **成员姓名/邮箱** | ✅ 能看到（取决于配置） | 精准钓鱼素材 |
| **成员部门信息** | ✅ 能看到（取决于配置） | 权限边界分析 |

### 实战利用：绘制组织架构图 {#实战利用绘制组织架构图}

企业认为“外部群是安全的”，但却忽略了 IM **开放 API** 可能存在的配置不当。攻击者可以利用这些公开接口对群成员信息进行枚举和收集。

**步骤：**

1. 找个理由混进外部群。
2. 利用 **IM 的 API**（可能存在权限配置不当的问题）去**枚举**群成员的详细信息。
3. 分析收集到的姓名、邮箱、部门信息，从而**绘制**目标公司的组织架构图。
4. 根据职位（如 IT、财务）进行 **精准定位钓鱼**。

> **核心思路：** 外部协作群是一个绝佳的**免费侦察入口**，为后续的 OAuth 攻击和横向渗透提供了高质量的“人名/邮箱”清单。

## OAuth 攻击：扫码即“授权点链接” {#oauth-攻击扫码即授权点链接}

### 先理解 OAuth 是什么 {#先理解-oauth-是什么}

OAuth 流程让你授权第三方应用，访问你在 IM 平台上的部分信息。

> **关键点：** 扫码授权 **本质上** 等同于你点击了一个特殊的授权链接。

### 攻击点 1：劫持跳转地址 (Redirect URI) {#攻击点-1劫持跳转地址-redirect-uri}

OAuth 流程中的一个关键参数是 `redirect_uri`，即授权码发送的目的地。

**攻击思路：** 如果我能将这个 `redirect_uri` 参数改成我自己的恶意网站，就能直接截获授权码。

**完整攻击流程：**

1. 攻击者 IM 发消息：“系统升级，需要重新授权，请点击链接。”
2. 受害者点击链接，进入真实的 IM 授权页面（信任度极高）。
3. 受害者点“同意授权”。
4. IM 平台将授权码发送到 **我的恶意网站**。
5. 攻击者用授权码换取永久访问令牌。
6. **结果：** 攻击者现在能以受害者身份操作 IM 平台了。

### 攻击点 2：授权页面 XSS {#攻击点-2授权页面-xss}

- **场景：** 某些 IM 平台的授权页面，可能因为开发者疏忽，对 URL 中的参数未进行严格过滤。
- **攻击 Payload（概念）：** 构造一个 OAuth 链接，在特定参数中注入 XSS 代码，使其在授权页面加载时触发。

**结果：**

1. 用户点击恶意 OAuth 链接。
2. 授权页面加载时，执行了注入的 JavaScript。
3. JavaScript 窃取用户的 Session Cookie 或 Token。
4. 攻击者利用窃取的 Cookie 直接登录用户账号，**完全绕过密码验证**。

## 客户端攻击：从浏览器到操作系统 {#客户端攻击从浏览器到操作系统}

### Electron 的秘密：披着软件外衣的网页 {#electron-的秘密披着软件外衣的网页}

现在的 IM 客户端很多都使用 **Electron** 框架开发。

- **Electron 是什么？** 简单说就是“把网页包装成桌面软件”。
- **危险在哪？** 正常的网页，JavaScript 只能操作浏览器；而 Electron 客户端如果配置不当，**前端 JavaScript 可以直接操作你的文件系统、执行系统命令！**

### 从 XSS 到执行命令 {#从-xss-到执行命令}

**如果客户端存在 XSS 漏洞，后果将是灾难性的：**

| 环境 | XSS 攻击效果 | 为什么？ |
| --- | --- | --- |
| **普通网页** | 偷 Cookie，弹窗 | JavaScript 被限制在沙箱内。 |
| **Electron 客户端** | 执行系统命令 | 开发者启用了 `nodeIntegration` 配置。 |

> **🔥 快速测试法：**<br> 在 IM 客户端的开发者工具（`Ctrl+Shift+I`）里输入 `typeof require`。如果返回 `'function'`，而不是 `'undefined'`，说明前端脚本被允许调用 Node.js 的功能，可能存在配置不当的问题。

### 协议劫持 {#协议劫持}

IM 客户端会注册自定义协议（如 `dingtalk://`、`lark://`），以便从浏览器唤起自身。

**历史漏洞案例（思路要记住）：**<br> 自定义协议的参数处理逻辑，如果缺乏安全检查，可能存在注入漏洞。例如，允许通过协议参数传递 `file://` 路径，从而导致点击链接直接唤起客户端并执行本地文件。虽然主流应用已修复，但**任何自定义协议的参数解析**都是潜在的攻击面。

## 组合攻击案例与总结 {#组合攻击案例与总结}

### 攻击思维训练：从功能到漏洞 {#攻击思维训练从功能到漏洞}

拿到一个 IM 功能，按这个清单过一遍：

- 这个功能的输入是什么？
- 输入怎么传递的？输出在哪里？
- 有没有特殊处理？（自动下载？协议唤起？）
- 权限边界在哪？（外部用户能访问吗？）

### 组合攻击案例 {#组合攻击案例}

**目标**：从外部协作群打到企业内网

1. **侦察：** 混入外部群，枚举成员信息，找到 IT 管理员邮箱。
2. **钓鱼：** 伪造 OAuth 授权链接，窃取 IT 管理员的访问令牌。
3. **横向：** 用管理员权限进入 IM 后台，利用**“批量消息”**功能，向全员发送恶意 LNK 文件 + 隐藏后门代码的 JPG 文件。
4. **提权：** 植入后门成功，内网横向移动，控制域控服务器。
