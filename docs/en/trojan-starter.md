# 木马，一切行动的基石

在开始这一章之前，我们先忘掉那些听起来很高大上的“无文件攻击”或者“内存逃逸”，又或者是你在黑客电影里看到的那种无影无踪的远程命令执行攻击。

让我们回到最朴素、最现实的场景：**作为攻击者，你需要让目标电脑执行你的命令。**

在 Windows 上，最直接的方法是什么？<br> 没错，就是想办法让目标**双击运行一个 `.exe` 文件**。

---

### 1. 为什么我们不用“网上下”的病毒 EXE？ {#h-1-为什么我们不用网上下的病毒-exe}

你可能会问：“既然目的是运行 EXE，那我直接在黑客工具箱里，或者网上找一个现成的病毒程序发过去不就行了吗？”

这是很多新手最初的思路，但很可惜，这种方法在今天的企业环境中几乎是无效的：

- **特征秒杀：** 杀毒软件（AV）和企业级防御系统（EDR）早就认识市面上所有已知的、默认生成的病毒文件。它们能识别这些文件的“指纹”（文件哈希、内部结构），你还没运行它就会被系统删除或隔离。
- **不灵活：** 这种 EXE 的通信和运行方式是固定的。一旦防御方封锁了它的通信端口或 IP，你就彻底失去了对目标电脑的控制。

**因此，现代红队或任何想进行定制化攻击的团队，都不会直接使用“原厂出厂”的恶意程序。**

---

### 2. 定制化是关键：什么是 C2 框架？ {#h-2-定制化是关键什么是-c2-框架}

为了解决上面的问题，专业的攻击者需要一个**定制化工具箱**。我们把这种工具箱称为 **C2 框架（命令与控制框架）**。

一个 C2 框架的最终产物，就是我们俗称的“木马（Trojan）”或“植入物（Implant）”——一个伪装成无害程序，却能悄悄连接回攻击者服务器的程序。

#### 🎓 从 Metasploit 到 Cobalt Strike：C2 的演变 {#从-metasploit-到-cobalt-strikec2-的演变}

在学习初期，你一定会接触到大名鼎鼎的 **Metasploit Framework (MSF)**。

- **Metasploit 的角色：** MSF 是一个**绝佳的学习平台和漏洞利用框架**，它拥有海量的漏洞利用模块。在初期的测试环境，它能帮你快速生成一个反弹 Shell 的 Payload（例如 `meterpreter`）。
- **Metasploit 在实战中的局限性（为什么没人用）：**
    1. **高检测率：** MSF 的 `meterpreter` 等核心 Payload 是全世界安全厂商的**重点监控对象**。它们的通信协议、内存特征、代码结构是固定的，任何一个用户被检测到，防御方就能立刻识别出所有 MSF Payload。
    2. **特征过于明显：** 无论是它的默认配置还是生成的代码，都带有明显的“指纹”，难以在绕过现代 EDR/AV 的情况下存活。

**结论：** MSF 适合**漏洞测试**，但不适合**隐蔽的红队行动**。

#### 商业 C2 的优势 (以 Cobalt Strike 为例) {#商业-c2-的优势-以-cobalt-strike-为例}

为了追求隐蔽性和灵活性，专业红队会使用商业 C2 框架，例如 **Cobalt Strike (CS)**。

- **核心优势：定制化流量与免杀：** CS 的 Payload 不像 MSF 那样是固定代码。它允许你使用 **Malleable C2 Profiles**（可塑 C2 配置文件）来定制通信流量。
    - 你可以告诉 C2：“把我的控制指令伪装成 Google 搜索请求的流量。”
    - 你可以告诉 C2：“把我的数据加密后，伪装成发往一张图片的请求。”
- **结论：** 在实战中仍不建议使用未经修改的CobaltStrike，其流量特征非常显著。

### 3. 核心逻辑：Shellcode 到底是什么？ {#h-3-核心逻辑shellcode-到底是什么}

当我们使用 C2 框架生成一个 **“初始载荷（Initial Payload）”** 时，我们不会让它生成一个完整的、容易被识别的 `.exe` 文件。相反，我们只让它生成**核心的“恶意逻辑代码”**。

你会得到一串看起来像乱码的十六进制数据：

```c
/* length: 894 bytes */
unsigned char buf[] = "\xfc\x48\x83\xe4\xf0\xe8\xc8\x00\x00\x00...";
```

**这串 `\xfc\xe8...` 就是 Shellcode。**

- **Shellcode 的本质：** 它是纯粹的机器码（Machine Code），是 CPU 能直接理解并执行的指令。
- **它的任务：** 极其简洁高效地完成一件事——**连接回你的 C2 服务器，让目标电脑“上线”**。
- **打个比方：**
    - **EXE (加载器)** 是一个**包装盒**，它负责伪装成正常文件，欺骗系统。
    - **Shellcode** 是里面的**电路板**，它是真正干活、建立隐蔽通道的核心。

---

### 4. 你的任务：写一把能发射子弹的“枪”（Loader） {#h-4-你的任务写一把能发射子弹的枪loader}

你不能直接双击 Shellcode。它只是一堆数据，需要一个程序来告诉 CPU：“嘿，把这些数据当成指令执行！”

这就引入了 **Loader（加载器）** 的概念。

一个最简陋的、新手入门级的加载器（Loader），本质上只需要做三件事：

1. **申请内存：** 跟操作系统要一块空地，而且这块地必须允许执行代码（`VirtualAlloc`）。
2. **搬运代码：** 把那串 C2 框架生成的 Shellcode 复制到这块空地上（`memcpy`）。
3. **开始执行：** 告诉 CPU，“从这里开始执行代码”（函数指针调用或 `CreateThread`）。

**总结：** 在红队初期，我们的工作流程就是：使用 C2 框架生成 **Shellcode**（子弹），然后自己编写一个足够灵活、能躲避杀软的 **Loader**（枪）来运行它。

---

### 5. 🏗️ 为什么我们不从“造一个 C2”开始？ {#h-5-️-为什么我们不从造一个-c2开始}

你可能会想：“既然 C2 这么重要，我是不是应该先学怎么写一个 C2 框架？”

**千万别！** 对于新手来说，这就像刚学会骑自行车，就立刻想徒手造一辆法拉利。

一个成熟的 C2 框架（哪怕是功能最基础的）是一个**庞大的分布式系统工程**。

#### C2 框架的“解剖学” {#c2-框架的解剖学}

一个标准的 C2 框架至少包含三个核心部分，每一部分都需要完全不同的技能树：

- **A. 服务端 (The Server / Teamserver)：** 这是“大脑”。需要掌握高并发网络编程（Go/Python/Java）、数据库和多线程处理。
- **B. 客户端/控制台 (The Client / UI)：** 这是“驾驶舱”。需要掌握前端或桌面 GUI 开发。
- **C. 植入物 (The Implant / Agent)：** 这是“间谍”。**Shellcode 就在这里！** 需要掌握 C/C++、Windows API 底层调用和内存管理。

#### 为什么要从 Shellcode/Loader 开始？ {#为什么要从-shellcodeloader-开始}

如果你一上来就想写 C2，你会因为同时面对太多复杂的技术（网络、数据库、加密、系统底层）而感到挫败。

**红队实战的最小单元，就是 Implant（植入物）。**

我们现在学的 Shellcode，就是 Implant 的“胚胎”形式。**只有先理解了最底层的 Shellcode 是如何在内存里“活下来”的，你未来才有能力去编写那种能躲过杀软的复杂 C2 Agent。**

#### 🧗 进阶之路：如果你未来想写 C2 {#进阶之路如果你未来想写-c2}

虽然我们现在还没法造车，但我可以先给你一张“造车图纸”。如果你在学完基础后，想挑战开发自己的 C2 框架，你需要按顺序点亮以下技能点：

- **Level 1: 基础入行（我们现在的阶段）：** 掌握 C/C++，理解 Windows 进程、线程、内存的基本概念。
- **Level 2: 功能开发：** 掌握 Socket 编程、熟悉 Windows API（如文件、进程操作）。
- **Level 3: 隐蔽与对抗（高级红队开发）：** 掌握加密学（流量伪装）、内存规避技术、以及协议伪装。
