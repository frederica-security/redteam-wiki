# 凭证获取 - 你手中的钥匙

在建立了持久化立足点后，我们的“潜伏期”结束了，现在开始收割最重要的战果：**凭证（Credentials）**。

凭证就像是您在目标网络中自由穿梭所需的各种“数字钥匙”。获取它们，比暴力破解密码要快得多、隐蔽得多。

本章，我们将聚焦于如何从 Windows 主机上窃取不同类型的钥匙，并解释为什么有些钥匙比另一些更有价值。

---

### 1. 凭证的分类与价值排序 {#h-1-凭证的分类与价值排序}

我们将在目标主机上寻找以下三类核心凭证，并按照其在实战中的“快速通行”价值进行排序：

| 价值排序 | 凭证类型 | 价值概述 | 实战效果 |
| --- | --- | --- | --- |
| **🥇 最高** | **会话凭据（Cookies/Token）** | 比如浏览器cookies，可以绕过登录密码和双因素认证（2FA），直接进入会话。 | 极高，无需触碰密码。 |
| **🥈 其次** | **系统凭据（Hash/Kerberos）** | 可用于横向移动。一旦拿到域管理员 Hash，即可控制整个网络。 | 较高，通常需要 SYSTEM 权限。 |
| **🥉 再次** | **应用密码（明文密码）** | 网站、邮箱、数据库等密码。虽然有价值，但使用时可能触发 2FA。 | 较高，需要解密。 |

### 2. 🔑 最高价值：浏览器凭据与会话劫持 {#h-2-最高价值浏览器凭据与会话劫持}

为什么浏览器凭据是最高价值？

> **原因：** 如今大多数系统都开启了**双因素认证 (2FA)**。如果您拿到密码直接登录，目标手机就会收到短信或推送通知，**打草惊蛇！**
>
> **Cookie/Token 的作用：** 它们代表了“用户已经通过验证”的当前会话状态。我们只需要拿到有效的 Cookie，就能跳过密码输入和 2FA 步骤，直接进入用户的邮箱、内网系统或 VPN 界面。

Chromium 内核浏览器（Chrome、Edge）是我们的首要目标，它们将敏感数据加密存储在本地的数据库文件中。

#### 2.1 存储机制：DPAPI 与 V20 的演变 {#h-21-存储机制dpapi-与-v20-的演变}

无论是存储的密码还是 Cookie，浏览器都使用一个**主密钥 (Master Key)** 进行加密。这个主密钥又被 Windows 的安全机制保护起来：

| 浏览器版本 | 保护机制 | 攻击原理 | 隐蔽性 |
| --- | --- | --- | --- |
| **V10/V11 (旧版)** | DPAPI 绑定用户凭据 | 只要以**相同用户身份**运行，即可简单调用 Windows API 解密。 | 低（操作简单，易被监控）。 |
| **V20 (新版)** | 应用程序绑定加密 | 密钥解密过程被转移到 **SYSTEM 权限服务**。只能通过 **进程注入** 或 **内存转储** 来获取。 | 极高（需复杂的内存或进程操作）。 |

对于入门者，最关键的知识点是：

> 🚨 **攻击目标不是加密文件本身，而是解密它的“钥匙”——主密钥。**

#### 2.2 实战获取手段：从磁盘到内存 {#h-22-实战获取手段从磁盘到内存}

由于 Chrome V20 的加固，攻击手法也变得更专业：

| 手法 | 目标 | 优点 |
| --- | --- | --- |
| **文件解密** | V10 主密钥 | 速度快，代码简单。适合老版本浏览器。 |
| **内存转储 (Minidump)** | 正在运行的 Chrome 进程内存 | 绕过 V20 磁盘加密。从内存中直接提取已解密的主密钥或明文数据。 |
| **进程注入/劫持** | V20 解密服务 | 模拟合法 Chrome 进程去向 **SYSTEM 服务**请求解密密钥。 |
| **CDP 窃取** | Chrome 调试端口 | 适合特定场景（如应用基于 Electron），直接通过 Web 协议获取当前会话的 Cookie。 |

### 3. 🛡️ 其次价值：系统凭据与横向移动 {#h-3-️-其次价值系统凭据与横向移动}

虽然浏览器凭据能让我们登录应用，但**系统凭据**才能让我们在整个内网中移动。

#### 3.1 🔐 LSA Subsystem (LSASS) {#h-31-lsa-subsystem-lsass}

`LSASS.exe` 是 Windows **本地安全认证子系统**的核心进程。当你输入密码登录后，Windows 会把你的 **NTLM Hash** 和 **Kerberos 票据**安全地存储在 LSASS 的内存中。

- **NTLM Hash：** 密码的单向散列值，不能逆推出原始密码，但可以用于**哈希传递 (Pass-the-Hash)**，即无需密码即可登录其他机器。
- **Kerberos 票据：** 在域环境中，它相当于一张**通行证**，允许您在一定时间内访问域内的其他资源。

#### 3.2 LSASS 内存转储（LSA Dump） {#h-32-lsass-内存转储lsa-dump}

这是获取系统凭证的经典方法：

1. 利用我们已有的高权限（SYSTEM）。
2. 将 `lsass.exe` 进程的内存完整地转储（Dump）成一个文件。
3. 将文件带回自己的机器，用专业工具（如 `Mimikatz`）离线分析，提取出所有登录用户的 Hash 和票据。
