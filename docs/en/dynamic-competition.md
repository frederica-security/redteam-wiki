# 动态对抗 - 行为分析何以可能

本章节建议搭配芙蕾德莉卡的安全学习科普视频观看 [https://www.bilibili.com/video/BV1z8CXBRE7H](https://www.bilibili.com/video/BV1z8CXBRE7H)

在上一章，我们通过混淆和白加黑（静态对抗），成功骗过了杀软的文件扫描。我们将“枪”拆散了藏进“蛋糕”里，顺利带过了安检。

但当你双击运行程序，试图把“枪”组装起来开火时，你发现周围的便衣警察（EDR）立刻扑了上来。

**这就是动态对抗。**

在动态对抗的世界里，杀软不再看你“长得像不像坏人”，而是看你**“有没有做坏事”**。无论你的代码加密得多么完美，你终究要调用系统 API，要申请内存，要联网，要读取文件。**只要你有动作，就会留下痕迹。**

本章将带你深入系统的底层，看看那些看不见的“监控探头”是如何工作的。

---

### 1. 上古时代的监控：SSDT Hook (Ring 0 的猫鼠游戏) {#h-1-上古时代的监控ssdt-hook-ring-0-的猫鼠游戏}

在早期的 Windows XP 时代，杀毒软件为了监控系统，做法非常野蛮。

- **原理：** Windows 想要执行核心操作（比如打开文件、创建进程），最终都要查询一张表——**SSDT (System Service Descriptor Table，系统服务描述符表)**。这张表里记录了所有内核函数的地址。
- **Hook 技术：** 早期的杀软（以及病毒）会直接修改这张表，把原本指向 Windows 内核的地址，改成指向杀软自己的驱动程序。
    - **流程：** 你调用 `OpenProcess` -> 跳转到杀软驱动 -> 杀软检查你是不是在抓 LSASS（读取密码） -> 杀软放行或拦截。
- **结局：** 这种做法非常不稳定。如果两个杀软同时修改这张表，或者修改出错，Windows 就会直接蓝屏（BSOD）。微软在 64 位系统中引入了 **PatchGuard (PG)** 技术，严禁任何人乱改内核表，标志着 SSDT Hook 时代的终结。

---

### 2. 现代法治社会：内核回调 (Kernel Callbacks) {#h-2-现代法治社会内核回调-kernel-callbacks}

微软禁止了 SSDT Hook，但杀软总得干活啊。于是微软说：“别乱改我家内核了，我给你们开正规接口。”

这就是现在的 **内核回调机制**。也是目前 EDR 监控的主流方式。

#### A. 进程与线程监控 (PsSetCreateProcessNotifyRoutine) {#a-进程与线程监控-pssetcreateprocessnotifyroutine}

- **原理：** 杀软向系统注册一个回调函数。每当有新进程创建（Create）或退出（Exit）时，Windows 内核会**主动通知**杀软。
- **场景：** 当你的 Loader 试图启动 `cmd.exe` 或 `powershell.exe` 时，EDR 也是第一时间知道的。

#### B. 句柄与对象访问监控 (ObRegisterCallbacks) 🚨 {#b-句柄与对象访问监控-obregistercallbacks}

- **这是红队的噩梦。**
- **原理：** 当一个程序试图获取另一个程序的**句柄 (Handle)** 时，内核会触发这个回调。
- **场景：** 当你试图使用 Mimikatz 读取 `lsass.exe`（本地安全机构子系统服务）的内存来抓取密码时，你必须先获取 `lsass` 的句柄。
    - EDR 的驱动在回调里一看：“哎？你一个陌生的 `temp.exe` 为什么要申请 `lsass` 的读写权限？”
    - **结果：** 直接剥夺你的权限，你的程序会收到“Access Denied（访问拒绝）”，操作失败。

#### C. 镜像加载监控 (PsSetLoadImageNotifyRoutine) {#c-镜像加载监控-pssetloadimagenotifyroutine}

- **场景：** 当你的程序试图加载一个 DLL 时（比如加载漏洞利用的 DLL），EDR 会被通知并进行检查。

---

### 3. 无处不在的摄像头：ETW (Event Tracing for Windows) {#h-3-无处不在的摄像头etw-event-tracing-for-windows}

如果说回调函数是“门卫”，那么 ETW 就是布满整个大楼的“高清摄像头”。

- **什么是 ETW？**<br> 它是 Windows 内置的一套极其强大的日志和追踪系统。原本是给开发者调试用的，现在被蓝队用来抓黑客。
- **它能看到什么？**<br> ETW 深入到了 .NET 运行时和各种系统组件内部。
    - **Cobalt Strike 的痛点：** CS 经常使用 `execute-assembly` 在内存中运行 C# 程序。在没有文件落地的情况下，传统的杀软很难查。
    - **ETW 的杀招：** .NET 运行时会通过 ETW 将**程序集的加载、方法的调用**甚至**恶意关键词**广播出来。EDR 只需要订阅这些事件，就能看见你在内存里偷偷跑了什么。
- **红队对策：** 所谓的“ETW Patching”技术，就是想办法在内存里把这个摄像头的线剪断（修改内存中的 ETW 发送函数，让它失效）。

---

### 4. 网络层的关卡：WFP (Windows Filtering Platform) {#h-4-网络层的关卡wfp-windows-filtering-platform}

你可能会发现，有时你的木马运行起来了，也没被杀，但就是**不上线**。这可能是 WFP 在作祟。

- **原理：** WFP 是微软提供的一套网络流量处理平台。它允许安全软件在数据包进入网卡之前，在内核层进行拦截、检查和修改。
- **监控深度：** 它不仅仅看 IP 和端口（像防火墙那样），它能看到发起网络请求的**进程是谁**，甚至能深入分析数据包的内容。
- **场景：** 你的木马试图连接 C2 服务器。虽然防火墙规则允许出站，但 EDR 的 WFP 驱动发现发起连接的是一个刚启动的、未签名的、行为可疑的进程，于是直接在内核层丢弃了数据包。

---

### 5. 降维打击：虚拟化对抗 (VT-x 与 Ring -1) {#h-5-降维打击虚拟化对抗-vt-x-与-ring-1}

如果说上面的对抗还是在同一个维度（Ring 3 - Ring 0 内核层）互搏，那么虚拟化技术就是**降维打击**。

代表产品：**360 核晶 (Core Crystal)**、**卡巴斯基硬件虚拟化**。

- **Ring 的概念：**
    - **Ring 3：** 用户模式（你的浏览器、木马都在这）。
    - **Ring 0：** 内核模式（操作系统、驱动程序在这）。
    - **Ring -1 (Root mode)：** 硬件虚拟化层（Hypervisor）。
- **原理：**<br> 利用 CPU 的硬件虚拟化技术（Intel VT-x），杀软会把自己安装在 **Hypervisor (Ring -1)** 层，然后把整个 Windows 操作系统跑在虚拟机里。
    - **上帝视角：** 杀软现在是操作系统的“宿主”。即使你作为一个顶级黑客，通过内核漏洞拿到了 Windows 的 Ring 0 权限（最高系统权限），试图关闭杀软驱动。
    - **降维压制：** 对不起，杀软在 Ring -1。你 Ring 0 的操作对它来说，就像是虚拟机里的程序想关闭宿主机一样，完全无效。它可以在更高维度监控内存、拦截指令。

---

### 💡 总结：红队该怎么办？ {#总结红队该怎么办}

看到这里，新手可能会感到绝望：*“天罗地网，这还怎么玩？”*

别灰心，攻防永远是动态平衡的。针对上述防御，红队也进化出了相应的战术：

1. **直接系统调用 (Direct Syscalls)：** 既然你监控了 Windows API（Ring 3 Hook），那我就跳过 API，直接去敲内核的大门，绕过用户层监控。
2. **自带驱动攻击 (BYOVD)：** Bring Your Own Vulnerable Driver。我带一个有漏洞的合法驱动进场，利用这个驱动的漏洞进入内核，去和 EDR 的驱动肉搏，致盲它。
3. **ETW/AMSI Patch：** 在内存中动态修改检测函数的代码，让它“瞎掉”
4. **杀软edr 0day** 即使是正经虚拟机也会被逃逸，何况是代码质量有时还比较堪忧的杀毒软件呢，哪怕开启了虚拟化技术，也存在被漏洞打掉的机会。
