在现代企业安全架构（如 XDR、UEBA、态势感知）的严密监控下，传统的暴力扫描和字典破解早已沦为“见光死”的自杀式行为。提到内网扫描，许多防守方的第一反应是“只要你敢用 Nmap 扫C/B段，我的 SOC 就能让你一秒封 IP / 掉木马 / 被应急”。

然而，实战复盘表明，“扫描与密码喷洒”非但没有过时，反而通过极度克制的**低频化**，成为了扩大内网战果最高效的起手式。我们将探索这一技巧的运用。

---

## 一、 暴力破解的前世今生：为何“喷洒”仍然有效？ {#一-暴力破解的前世今生为何喷洒仍然有效}

要理解这项技术的生命力，必须厘清它与传统暴力破解（Brute Force）的本质区别。

### 传统手法（已被淘汰的“单点爆破”） {#传统手法已被淘汰的单点爆破}

- **原理**：攻击者锁定一个高价值目标（如 `Administrator`），使用包含成千上万个密码的字典，对其进行高频连续尝试。
- **致命弱点**：现代 Windows Active Directory (AD) 域环境默认开启了“账户锁定策略”（例如：连续失败 5 次即锁定 30 分钟）。垂直爆破不仅会在极短时间内导致目标账户被锁定（直接阻断业务，引发 IT 部门高度警觉），还会在域控的安全日志中留下密集的 **Event ID 4625（登录失败）** 或 **Event ID 4740（账户被锁定）** 告警。SIEM 系统拦截这种单一维度的频率异常如同探囊取物。

### 密码喷洒 {#密码喷洒}

- **原理**：**转换攻击维度（从“垂直”变为“水平”）**。攻击者手里只有一个或几个极大概率存在的弱口令（如 `1qaz@WSX`），去**遍历尝试内网中的成百上千个不同账户**。
- **低频率**：每个账户在几个小时内只经历一次失败的登录尝试，完美绕过了 AD 的账户锁定阈值（通常是 3-5 次）。

## 二、 信息资产的拼图与协议狂舞 {#二-信息资产的拼图与协议狂舞}

既然不能盲目扫描，攻击者如何获取精准的喷洒目标？答案是**利用系统天然的、未鉴权的查询接口（Null Session）与枚举机制**。

### 1. 数据的桥梁：寻找合法的信息集散地 {#h-1-数据的桥梁寻找合法的信息集散地}

在喷洒之前，红队必须先获取一份绝对准确的“域用户名单”。高级攻击者不会使用敏感的端口扫描，而是通过合法协议“套取”名单：

- **LDAP 匿名绑定 / 认证绑定**：如果域环境配置不当允许匿名绑定，或者红队已经掌握了一个极其普通的低权限账户，就可以通过 LDAP 协议直接拉取整个活动目录的 `sAMAccountName` 属性。
- **RPC 协议的 RID 循环（RID Cycling）**：利用 `rpcclient` 或相关工具，通过枚举相对标识符（RID，通常从 1000 开始递增），向域控发送合法的 SID 解析请求。即使在受限环境中，也能硬生生把所有存活的用户名给“问”出来。

### 2. 精准引爆：针对性的喷洒策略 {#h-2-精准引爆针对性的喷洒策略}

拿到名单后，攻击者并不会立刻全量喷洒，而是会进行数据清洗（如剔除已经禁用的账户 `userAccountControl: 514`），然后构造参数进行打击。

以 `NetExec` (原 CrackMapExec) 或自定义脚本为例，其执行逻辑往往如下：

```python
# 伪代码：现代喷洒工具的核心逻辑
users = Get_Active_Domain_Users(LDAP_Target)
passwords = ["Welcome123", "Spring2024!"]

for password in passwords:
    for user in users:
        # 加入随机的睡眠时间以规避时间序列分析
        sleep(random_jitter(10, 60))

        # 尝试通过特定协议认证
        result = Attempt_Auth(user, password, protocol="SMB")

        if result == SUCCESS:
            Log_Loot(user, password)
            # 停止对该用户的喷洒，避免后续操作增加暴露风险
            users.remove(user)
```

## 三、 演变与进化：Kerberos 预身份验证的“合法后门” {#三-演变与进化kerberos-预身份验证的合法后门}

随着微软 Defender for Identity (MDI) 等高级域控监控组件的普及，传统的基于 SMB 协议（如 445 端口）的密码喷洒开始变得危险。因为 SMB 登录失败会产生明确的 4625 日志，且带有清晰的 Source IP 和 Workstation Name。

为了应对这一挑战，红队开发出了基于 **Kerberos 协议88 端口**的喷洒技术（如 `Kerbrute` 工具的底层逻辑）。

1. **定位弱点**：Kerberos 认证的第一步是客户端向 KDC（域控）发送 `AS-REQ` 请求。如果开启了预身份验证（Pre-Authentication），客户端需要用自己密码的 Hash 加密一个时间戳发送过去。
2. **无害的 AS-REQ**：攻击者在本地将候选密码（如 `1qaz@WSX`）转换为 NTLM/RC4 Hash，然后加密时间戳，打包成合法的 `AS-REQ` 数据包直接扔给域控。
3. **遥测的隐蔽性**：

- 如果密码**错误**：域控会返回一个 `KDC_ERR_PREAUTH_FAILED`，产生的是 **Event ID 4771**（Kerberos 预身份验证失败）。
- **降维优势**：在许多企业的日志收集策略中，4771 日志由于日常产生量极其巨大（员工锁屏恢复、手机连 WiFi 都会产生），往往没有被送入 SIEM 进行高优先级告警，甚至不被采集。攻击者精妙地利用了**日志审计的成本盲区**。

## 四、 局限性与实战意义 {#四-局限性与实战意义}

正如在实际攻防中所发现的，密码喷洒并非银弹，它有着极其明确的边界：

1. **MFA (多因素认证) 的绝对压制**：如果目标企业的所有入口（VPN、OWA、远程桌面）都强制开启了 MFA，那么即使喷洒拿到了密码，也无法建立初始立足点。
2. **密码复杂度的博弈**：如果企业严格执行了长密码和禁止包含公司名/年份的密码策略，基于规律猜测的字典将彻底失效。
3. **实战中的真正用途**：在大型内网中，**木桶效应永远存在**。它极大概率能帮您找到一个外包员工、一个遗忘的测试账户、或者一个没有配置 MFA 的老旧内网 Web 系统的登录凭据。这就是它从新手用到退役的原因。
